# collect-jira — выгрузить всё по задаче из Jira и КБ

Собирает в `материалы/` задачи всё, что есть по её ключу Jira: саму задачу, подзадачи,
связанные задачи, статьи КБ по ссылкам, их дочерние страницы, комментарии и **все вложения**,
сколько бы ни было в глубину. Выгрузка — через MCP-сервер Atlassian (инструменты `jira_*` и
`confluence_*`; у сервера свой префикс, например `mcp__kb-liga__`). `curl` — только для двух
случаев ниже, скриптом `fetch.sh`.

Пишет только в `материалы/jira/`, `материалы/кб/` и `материалы/индекс.md`. В Jira и КБ ничего
не меняет: инструменты правки и загрузки (`confluence_update_page`, `…_upload_…`) не вызывает.

## Раскладка

```
материалы/
  индекс.md                     очередь, дерево связей, внешние ссылки, что не выгрузилось
  jira/<КЛЮЧ>/
    карточка.md                 поля, описание, подзадачи, связи, вложения, комментарии
    файлы/                      вложения задачи
  кб/<id>_<название>/
    статья.md                   шапка, текст (markdown), список вложений
    исходник.html               исходник страницы: в нём ссылки и макросы, которых нет в md
    комментарии.md
    файлы/                      вложения статьи
```

Папки плоские — по ключу или id, иерархия — только в `индекс.md`: так один объект не
выгружается дважды. `<название>` в имени папки КБ — из заголовка статьи: нижний регистр, пробелы
— дефис, без `/ \ : * ? " < > | [ ]`, несколько дефисов подряд — один, не длиннее 60 символов; длиннее — обрезать по последнему
дефису в пределах 60, без дефиса на конце; если в первых 60 символах дефиса нет — резать ровно
по 60:
«[МП] 27.07.2026 - Протокол встречи» → `мп-27.07.2026-протокол-встречи`.

## Порядок

1. Задача — всё, что в аргументах после `collect-jira`: полный путь к папке задачи или её
   номер. Аргумента нет — последние задачи и вопрос «Какую задачу выгрузить?» по шагу 1
   `steps/analyze.md`. Найди задачу `locate.sh` по шагу 2 того же файла;
   первая строка не `FOUND` — доложи по его таблице и остановись.
2. Строки состояния после `FOUND`:
   - `jira=none` — в `задача.md` нет строки `**Jira:**`; скажи, что выгружать нечего, и
     остановись;
   - `task=missing` — скажи и остановись; `task=empty` выгрузке не мешает;
   - `archived=yes` — спроси выбором **Не трогать (рекомендую)** · **Выгружать всё равно**;
   - `materials=done` — выгрузка уже есть. Спроси выбором **Оставить (рекомендую)** ·
     **Обновить заново**. Оставить — остановись. Обновить — убери прошлую скриптом и иди
     дальше с чистого листа (`MOVED` — скажи, куда ушла, `to=`; иначе перескажи и стой):

     ```
     sh scripts/archive-materials.sh '<папка задачи>'
     ```

   - `materials=partial` — прошлая выгрузка прервалась. Прочитай `материалы/индекс.md` и
     продолжай с первой неотмеченной строки очереди; счёт объектов — из `objects` шапки.
3. **Проверка MCP** — первым делом, до записи файлов: `jira_get_issue` по ключу задачи. Нет
   инструментов Atlassian, ошибка соединения или авторизации — **стоп**: «MCP Atlassian не
   отвечает: <ошибка>. Подключи его (`/mcp` → reconnect) и запусти `collect-jira` снова».
   Ничего не пиши и в обход MCP не ходи. Задачи с таким ключом нет — скажи и остановись.
4. Новая выгрузка — заведи `материалы/индекс.md` по шаблону
   `templates/materials-index.md`: `__JIRA__` — ключ, `__TITLE__` — название
   задачи из Jira, `__DATE__` — сегодня (`ГГГГ-ММ-ДД`). В очередь первой строкой — сама задача.
5. Обходи очередь по порядку — объект за объектом, по разделам «Задача Jira» и «Статья КБ».
   После **каждого** объекта обнови `индекс.md`: отметь строку очереди `[x]` с путём, допиши
   новые строки очереди и ветку дерева, `objects` +1, `updated`. Так обрыв в любой момент
   ничего не теряет.
6. Новый объект ставь в очередь, только если его ещё нет ни в очереди, ни в дереве. Статью КБ,
   известную по названию (`kb.title`) или короткой ссылке (`kb.tiny`), сначала найди
   (`confluence_get_page` с `title` и `space_key` или с короткой ссылкой в `page_id`) и
   сравнивай по id. Пространство `-` — пространство статьи, где нашлась ссылка.
7. **Пауза каждые 50 объектов** (50, 100, 150…). Остановись и напиши обычным сообщением:
   «Порог <N> пройден. Выгружено <N> объектов: <сколько задач Jira, сколько статей КБ, сколько
   файлов>. Последним выгружен <вид, ключ или id, название>. В очереди <M>:» — и список
   очереди, по строке: вид, ключ или id, название, откуда пришёл. Затем спроси выбором:
   - **Дальше (рекомендую)** — продолжай до следующего порога;
   - **Выкинуть часть очереди** — что выкинуть, владелец пишет в «Другое»; эти строки
     перенеси в «Не выгружено» с пометкой «выкинул владелец» и продолжай;
   - **Хватит** — всю оставшуюся очередь перенеси в «Не выгружено» («остановлено владельцем»)
     и иди в шаг 8.
8. Очередь пуста — в шапке `status: done`, `updated` — сегодня. Доложи: сколько задач Jira,
   статей КБ и файлов выгружено, сколько скачано `curl`, что не выгрузилось и почему, путь к
   `индекс.md`. Дальше по задаче — `analyze`.

Ошибка MCP посреди обхода: обрыв соединения или авторизации — стоп, как в шаге 3: индекс уже
сохранён со статусом `partial`, повторный запуск продолжит с того же места. Ошибка про один
объект (нет доступа, нет такой страницы или задачи) — запиши его в «Не выгружено» с причиной и
иди дальше.

## Ответ MCP: в разговоре или в файле

Ответ MCP **никогда не перепечатывай** — файл пишет скрипт, тексты в нём как есть, целиком.
Виды: `jira` — `jira_get_issue`, `kb` — `confluence_get_page` (markdown), `kb-raw` — он же с
`convert_to_markdown` false, `kb-comments` — `confluence_get_comments`.

Большой ответ Claude Code не показывает, а сохраняет в файл и пишет путь
(`…/tool-results/…`) — отдай файл скрипту:

```
sh scripts/render.sh <вид> '<файл ответа>' '<папка объекта>'
```

Ответ пришёл в разговор — скрипт достанет его из журнала сессии сам, по виду и ключу Jira или id
статьи из вызова. Сессия — id из `SKILL.md` (раздел «Сессия»); там пусто — id из любого пути
`…/<id сессии>/tool-results/…` этой сессии:

```
sh scripts/from-session.sh '<id сессии>' <вид> '<ключ или id>' '<папка объекта>'
```

Если ты не Claude Code (журналы `~/.claude/projects/` недоступны) — запроси у пользователя путь к `.jsonl`-журналу явно или пропусти выгрузку сессии, пометив в отчёте «сессия не выгружена».

| Вывод | Что сделать |
| --- | --- |
| `WROTE <файл>` | готово |
| `EMPTY` | комментариев нет — файл не нужен |
| `IN_FILE <путь>` | ответ всё же в файле — `render.sh` с этим путём |
| `NOT_FOUND`, `NO_JOURNAL` | проверь id сессии и ключ; не вышло — объект в «Не выгружено» |
| любой другой | перескажи вывод, объект в «Не выгружено» |

## Задача Jira

1. `jira_get_issue`: `fields` —
   `summary,status,issuetype,priority,assignee,reporter,created,updated,labels,components,fixVersions,parent,subtasks,issuelinks,attachment,description`,
   `include` — `comments,remote_links`, `comment_limit` — 100, `update_history` — false.
   Пиши `jira/<КЛЮЧ>/карточка.md`.
2. Подзадачи и дети: `jira_search` с `parent = <КЛЮЧ>` (`limit` 50, дальше `start_at`); у
   эпика — ещё `"Epic Link" = <КЛЮЧ>`. В очередь — все, кто бы ни был исполнителем.
3. В очередь же: родитель, эпик, связанные задачи (`issuelinks`), удалённые ссылки на КБ и
   Jira; остальные удалённые ссылки — во «Внешние ссылки».
4. Ссылки из текста — скриптом по карточке; проект — часть ключа до дефиса (`MS`):

   ```
   sh scripts/links.sh '<папка>/карточка.md' '<ПРОЕКТ>'
   ```

   `kb.id`, `kb.title`, `kb.tiny`, `jira` — в очередь; `url` — во «Внешние ссылки».
5. Вложения — по разделу «Вложения» ниже.

## Статья КБ

1. `confluence_get_page` по id (markdown, с метаданными) → `кб/<id>_<название>/статья.md`.
2. `confluence_get_page` по id с `convert_to_markdown` false и `include_metadata` false →
   `исходник.html` в той же папке. Ссылки на другие статьи в markdown теряются — ищи их в
   исходнике:

   ```
   sh scripts/links.sh '<папка>/исходник.html' '<ПРОЕКТ>'
   ```

   Выход — как у задачи Jira, шаг 4.
3. `confluence_get_comments` → `комментарии.md` скриптом, вид `kb-comments`. Комментариев нет —
   скрипт файл не создаёт (`EMPTY`).
4. `confluence_get_page_children` (`limit` 50, дальше `start`) — все дочерние страницы в
   очередь.
5. Вложения — по разделу «Вложения» ниже. Список с размерами и id — раздел «Вложения» в
   `статья.md` (из метаданных статьи). `confluence_get_attachments` очень тяжёлый — зови его,
   только если в этом списке 100 вложений и больше: список мог обрезаться (`limit` 100, дальше
   `start`).

## Вложения

Каждое вложение — в `файлы/` своего объекта, под своим именем, с проверкой размера из списка
вложений. Вложение draw.io (`application/vnd.jgraph.mxfile`) без расширения — допиши `.drawio`.

- **КБ** — `confluence_download_attachment` по id, по одному. Claude Code сам кладёт файл на
  диск и пишет путь: «saved to <путь>» или «[Image: source: <путь>]». Перенеси:

  ```
  sh scripts/save.sh '<путь>' '<папка объекта>/файлы' '<имя>' <размер>
  ```

- **Jira** — `jira_download_attachments` по ключу, разом все вложения задачи. Картинки
  приходят файлами с путём — `save.sh`, как выше. Ответ ушёл в файл (`…/tool-results/…`) —
  достань из него остальное:

  ```
  sh scripts/decode.sh '<файл ответа>' '<папка объекта>/файлы'
  ```

  Маленькие не-картинки приходят base64 прямо в разговор — **не перепечатывай** их, качай
  `fetch.sh` (ниже). Если у задачи вложения — только такие маленькие не-картинки,
  `jira_download_attachments` не зови, сразу `fetch.sh`.
- **Больше 50 МБ** — MCP их не отдаёт; сразу `fetch.sh`.

`curl` — только эти два случая, и каждый такой файл — строкой в «Скачано curl»:

```
sh scripts/fetch.sh '<ссылка из списка вложений>' '<папка объекта>/файлы' '<имя>' <размер>
```

Ссылка — `url` вложения Jira или `download_url` вложения КБ (относительная — можно как есть).

| Вывод `save.sh` / `decode.sh` / `fetch.sh` | Что сделать |
| --- | --- |
| `SAVED` / `SAME <путь>` + `size=` | файл на месте |
| `DECODED <N>` + строки `SAVED`/`SAME` | сверь с списком вложений: чего нет — `fetch.sh` |
| `SIZE_MISMATCH expected=… got=…` | файл битый или не тот: скачай `fetch.sh`. Снова не сошлось, но `got=` тот же, что от MCP, — файл целый, а размер в списке устарел: файл оставь, в строке «Скачано curl» допиши «в списке <expected>, скачано <got>». `got=` другой — «Не выгружено» с размерами |
| `NOT_MATERIALS` | папка не внутри `материалы/` — путь собран неверно, исправь |
| `NO_CONFIG` / `CONFIG_NO_KEY … atlassian.env` / `ENV_MISSING` | `fetch.sh` не знает адресов и токенов. Скажи владельцу добавить в шапку `.claude/sae.local.md` строку `atlassian.env: <путь к .env MCP-сервера Atlassian>`; файл сам не правь. Вложение — в «Не выгружено», иди дальше |
| `FOREIGN_HOST` | ссылка не на Jira и не на КБ — токен туда не уходит; во «Внешние ссылки» |
| `DOWNLOAD_FAILED`, любой другой | «Не выгружено» с текстом ошибки, иди дальше |

## Чего не делать

- Не ходить в Jira и КБ в обход MCP: `curl` — только `fetch.sh` и только в двух случаях выше.
  MCP не отвечает — стоп, а не обход.
- Не менять ничего в Jira и КБ.
- Не сокращать и не пересказывать выгружаемые тексты; не перепечатывать ответы MCP и base64.
- Не писать вне `материалы/jira/`, `материалы/кб/`, `материалы/индекс.md`; `задача.md` и
  `анализ.md` не трогать.
- Не выгружать объект второй раз в одной выгрузке.
- Не проходить порог 50 без паузы и вопроса владельцу.

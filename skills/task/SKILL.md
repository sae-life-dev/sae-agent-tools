# task — задачи в папках

Работай только по инструкциям этого скилла и его файлам. Внешние файлы для работы скилла не
нужны и не ищутся. Инструменты и правила человека при этом действуют как обычно.

Что инструкция велит показать перед вопросом выбором (предупреждения, таблицу, доклад), — сначала
напиши обычным сообщением, затем задай вопрос. В сам вопрос клади только вопрос и короткое
пояснение к нему: таблицу и список предупреждений окно выбора не покажет.

Папку задач проекта скрипты берут из `.claude/sae.local.md` в рабочей папке сессии (ключ
`task.dir`); записывает её туда `init`. Там же ключ `atlassian.env` — путь к `.env`
MCP-сервера Atlassian, его пишет владелец; нужен `collect-jira`. Руками этот файл не правь и
пути из него сам не подставляй — их читают скрипты.

## Правила задачи

В папке задачи может лежать `правила-задачи.md` — правила владельца для работы над этой
задачей. Каждое действие над задачей (`collect-jira`, `analyze`, `split`, `next`), как только
`locate.sh` вернул `FOUND`, сначала читает `<папка задачи>/правила-задачи.md` и дальше выполняет
эти правила всё время работы по задаче:

- правила владельца выше умолчаний инструкций этого скилла: как докладывать, что делать перед
  подзадачей, о чём спрашивать;
- форму, которую проверяют скрипты (шапки, метки, таблица раздела 7, отметки шагов), правила не
  отменяют; если правило с ней спорит — скажи об этом и спроси владельца, сам не выбирай;
- файла нет (задача заведена до него) или в нём одни заголовок и комментарий — работай как
  обычно, файл не создавай;
- файл пишет и правит только владелец.

## Сессия

Id этой сессии: `${CLAUDE_SESSION_ID}`. Нужен `collect-jira`, чтобы скрипт достал ответ MCP из
журнала сессии, а не перепечатывать его.

## Мультиагентность

Скилл работает в любом агенте (Claude Code, субагенты, другие IDE-агенты): всё состояние —
только файлы задачи на диске, скрипты не зависят от агента и его памяти. Правила:

- Начинай любое действие со скриптов, а не с памяти или конспекта: `locate.sh` и `next.sh`
  печатают состояние задачи и `hint=` — какой файл `steps/` вести. `hint=` есть и в отказах
  (`NO_SUBTASKS` и др.): следуй ему, не додумывай маршрут сам.
- Методичку `steps/<действие>.md` читай из папки скилла целиком перед выполнением — не по
  конспекту и не по памяти: конспекты устаревают.
- Тяжёлые и объёмные фазы (выгрузка `collect-jira`, разбор материалов для `analyze`,
  реализация шага подзадачи) можно делегировать субагентам: субагенту передай папку задачи,
  нужный файл `steps/…` и требование «меняй только то, что разрешает методичка».
- Приёмка всегда у главного агента с владельцем: `mark.sh` (галочки шагов и признаков),
  `close.sh`, согласование микрошагов и ответы на вопросы раздела 6 — субагенту не отдавай.
- Субагент закончил — сверь фактами его доклад (файлы на диске, вывод скриптов), затем
  продолжай по `steps/next.md`.
- В агенте без этого скилла нативно (например, чужая IDE): скрипты можно запускать любым
  способом запуска shell из корня проекта; `hint=`-строки ведут и его.

## Разбор команды

Аргументы: `$ARGUMENTS`

Первое слово аргументов — действие, остальное — его параметры.

| Действие | Что делает | Инструкция |
| --- | --- | --- |
| `init [путь]` | делает папку папкой задач и запоминает её для проекта; без пути — спрашивает | `steps/init.md` |
| `new <название> [--jira <ключ>]` | заводит в папке задач задачу `<NNN>_<имя>/` с `задача.md`; номер — следующий по порядку; с ключом Jira — `<NNN>_<КЛЮЧ>_<имя>/`, без `--jira` — спрашивает | `steps/new.md` |
| `collect-jira [путь\|номер]` | по ключу Jira из `задача.md` выгружает через MCP в `материалы/` задачу, подзадачи, связанные задачи, статьи КБ по ссылкам вглубь, комментарии и все вложения; пауза каждые 50 объектов; прерванную — продолжает; без номера — выбор из трёх последних задач | `steps/collect-jira.md` |
| `analyze [путь\|номер]` | разбирает задачу и пишет `анализ.md`; `задача.md` пустой, а ключ Jira есть, — предлагает заполнить его по Jira и КБ; без номера — выбор из трёх последних задач | `steps/analyze.md` |
| `split [путь\|номер]` | по разделу 7 анализа создаёт `подзадачи/NN_<имя>.md` с шагами; повторный запуск — только новые; без номера — выбор из трёх последних задач | `steps/split.md` |
| `next [путь\|номер]` | сначала `scripts/next.sh` — печатает маршрут (`ROUTE …` + `hint=…`); дальше определяет этап задачи и предлагает продолжение меню; `задача.md` пустой, а ключ Jira есть, — предлагает заполнить его по Jira и КБ; когда подзадачи есть — выбор: работа или подробное согласование всей задачи по микрошагам (итог в `согласование.md`); ведёт работу по шагам подзадач, закрывает подзадачи и задачу (в `_архив/`); без номера — выбор из трёх последних задач | `steps/next.md` |

- Действие есть в таблице — прочитай его инструкцию и выполни по ней.
- Аргументов нет — покажи таблицу действий и спроси, что сделать. Сам ничего не делай.
- Действия нет в таблице — скажи, что такого действия пока нет, и покажи таблицу.

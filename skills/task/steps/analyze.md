# analyze — разобрать задачу

Пишет в папке задачи `анализ.md` по шаблону `${CLAUDE_SKILL_DIR}/templates/analysis.md`. Больше
ничего не пишет.

## Порядок

1. Задача — всё, что в аргументах после `analyze`: полный путь к папке задачи или её номер.
   Папка с именем из одних цифр — передай её как путь: `./123`. Номер в ответах пиши
   полностью, с нулями: `024`. Аргумента нет — возьми последние задачи:

   ```
   sh ${CLAUDE_SKILL_DIR}/scripts/recent.sh
   ```

   Эту таблицу читают и `split`, и `next`; вопрос — по действию: «Какую задачу разобрать?»,
   «…разбить?», «…вести?».

| Вывод | Что сделать |
| --- | --- |
| `RECENT <папка задач>` + пары `task=<номер> <папка>`, `title=<название>` | спроси выбором, какую задачу: вариант на задачу — «`<номер>` `<название>`», по порядку вывода; описание — «или впиши номер в „Другое“». Задача одна — второй вариант «Другая задача» с тем же описанием. Ответ — номер или папка — аргумент шага 2; отказ в «Другое» — остановись |
| `EMPTY <папка задач>` | задач нет; предложи завести: `/sae:task new <название>`. Остановись |
| `NO_CONFIG` / `CONFIG_NO_KEY` / `TASKS_MISSING` / `TASKS_UNMARKED` | как в таблице шага 2; попроси номер с путём или полный путь к задаче |
| любой другой | перескажи вывод как есть и остановись |

2. Найди задачу скриптом, аргумент — в одинарных кавычках (кавычку внутри — как `'\''`):

   ```
   sh ${CLAUDE_SKILL_DIR}/scripts/locate.sh '<путь или номер>'
   ```

   Первая строка не `FOUND` — доложи и остановись; `AMBIGUOUS` — спроси и повтори этот шаг:

| Вывод | Что сказать |
| --- | --- |
| `FOUND <папка>` | идём дальше; ниже строки состояния |
| `NOT_FOUND <номер>` | задачи с таким номером нет в папке задач (`tasks.root=`); попроси проверить номер или дать путь |
| `AMBIGUOUS <номер>` + папки, по строке на каждую | номер есть у нескольких папок; спроси выбором, какая нужна: вариант на папку — её имя, у папки из `_…/` — вместе с ней (`_архив/002_двойник`), описание — полный путь. Папок больше четырёх — первые четыре вариантами, остальные перечисли в вопросе, путь — в «Другое». Ответ — полный путь — аргумент этого шага; отказ в «Другое» — остановись |
| `NO_CONFIG <файл>` | папка задач для этого проекта не настроена; дай полный путь к задаче или сначала `init` |
| `CONFIG_NO_KEY <файл> task.dir` | в настройках нет пути к папке задач; полный путь к задаче или `init` |
| `TASKS_MISSING <папка>` | в настройках указана папка, которой нет; `init` заново или полный путь |
| `TASKS_UNMARKED <папка>` | папка из настроек не помечена как папка задач; `init` заново или полный путь |
| `NO_DIR` / `NOT_DIR` / `NOT_TASK <путь>` | по пути нет папки задачи (`NOT_TASK` — нет `задача.md`); попроси проверить |
| любой другой | перескажи вывод как есть |

3. Строки состояния после `FOUND`:
   - `task=empty` — в `задача.md` только заготовка. Скажи, что сначала её заполняет владелец
     («Что хочу», «Как пойму, что готово»), дай путь к файлу и остановись. Анализ по пустой
     постановке не пишется.
   - `task=missing` — в папке нет `задача.md`. Скажи об этом и остановись; файл сам не
     создавай.
   - `archived=yes` — задача в архиве. Скажи об этом и спроси выбором: **Не трогать
     (рекомендую)** · **Разбирать всё равно**. Дальше — только по второму; первый или ответ в
     «Другое», который не разрешает разбор, — остановись.
   - `analysis=exists` — анализ уже есть. Спроси выбором: **Дополнить (рекомендую)** ·
     **Написать заново**. Отказ в «Другое» — остановись, ничего не меняя.
     - Дополнить — работай в существующем `анализ.md`: номера разделов, фактов, вариантов,
       вопросов и подзадач не меняй, новые добавляй следующими номерами; отвеченные вопросы
       не трогай.
     - Написать заново — убери старый скриптом и пиши с чистого листа:

       ```
       sh ${CLAUDE_SKILL_DIR}/scripts/archive-analysis.sh '<папка задачи>'
       ```

       `MOVED …` — скажи, куда ушёл старый анализ (`to=`). Иначе — перескажи вывод и остановись.
4. Прочитай `задача.md` целиком. Постановка — только оттуда; чего там нет, но нужно для
   решения, — в вопросы.
5. Исследуй: код, документацию, базы знаний — любыми инструментами человека. Код и чужие файлы
   **только читай**. Каждый факт проверь сам и запиши, где проверено; догадку фактом не
   выдавай.
6. Напиши `анализ.md` в папке задачи по шаблону:
   - заголовок — `Анализ: <заголовок из задача.md без «Задача: »>`;
   - «Коротко» — первым, 3–5 предложений, понятных без чтения остального;
   - **все 7 разделов, номера постоянные**; раздел, которому нечего сказать, не удаляй, а пиши
     в нём «нет: потому что …»;
   - схемы mermaid — там, где они понятнее текста; обязательных нет;
   - выноски `> [!NOTE]` и подобные не используй — только цитаты с эмодзи:
     💡 главное, ℹ️ пояснение, ❓ открытый вопрос, ⚠️ риск или предупреждение;
   - вопросы — каждый своей цитатой: `> ❓ **В1. <Тема>.** <вопрос>`; рекомендацию, если она
     есть, — в том же вопросе;
   - раздел 7 — таблица `П1, П2…`, если работу есть смысл делить; если нет — «нет: потому что
     …» (с этих слов строка начинается). Таблицу по ней читает `split`, поэтому вид строгий:
     одна таблица, столбцы ровно как в шаблоне — `№ | Подзадача | Где | Зависит от | Размер`, `|`
     по краям строк; номер — `П<N>`, без повторов; «Зависит от» — номера `П<N>` через запятую или
     `—`; `|` внутри ячейки — как `\|`;
   - заглушки шаблона `<…>` не оставляй.
7. Доложи: путь к `анализ.md`, «Коротко» и список открытых вопросов с номерами.

## Ответы на вопросы

Владелец ответил на вопрос — запиши ответ в `анализ.md` у этого вопроса и обнови разделы,
которые от него зависят (решение, риски, разбивка, «Коротко»):

```
> ✅ **В1. <Тема>.** <вопрос как был>
>
> **Ответ (ГГГГ-ММ-ДД):** <ответ>
```

Вопрос не удаляй и не перенумеровывай.

## Чего не делать

- Не писать ничего, кроме `анализ.md` (и `материалы/` через скрипт при «заново»).
- Не править `задача.md`: его пишет только владелец.
- Не создавать подзадачи, план и карточку: у них свои этапы.
- Не менять код и чужие файлы, даже если по ходу нашлась очевидная ошибка: записать её в
  анализ.

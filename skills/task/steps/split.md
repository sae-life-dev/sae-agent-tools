# split — разбить задачу на подзадачи

Создаёт в папке задачи `подзадачи/NN_<имя>.md` по строкам раздела 7 `анализ.md`: строка `П1` —
файл `01_…`. Заготовку создаёт скрипт, остальное в ней дописываешь ты. Больше ничего не пишет.

Запуск команды и есть согласие владельца: список не показывай на одобрение и не переспрашивай.

## Порядок

1. Задача — всё, что в аргументах после `split`: полный путь к папке задачи или её номер.
   Папка с именем из одних цифр — передай её как путь: `./123`. Номер в ответах пиши
   полностью, с нулями: `024`. Аргумента нет — возьми последние задачи и спроси «Какую задачу
   разбить?» по шагу 1 `steps/analyze.md`; выбранная — аргумент шага 2.
2. Найди задачу скриптом, аргумент — в одинарных кавычках (кавычку внутри — как `'\''`):

   ```
   sh scripts/locate.sh '<путь или номер>'
   ```

   Первая строка не `FOUND` — доложи по таблице из `steps/analyze.md`
   (шаг 2) и остановись; `AMBIGUOUS` — выбор по той же таблице и снова этот шаг. После `FOUND`
   проверь строки состояния по порядку, первая сработавшая решает:
   - `task=empty` или `task=missing` — скажи, что сначала владелец заполняет `задача.md`, затем
     `analyze`; остановись;
   - `analysis=none` — скажи без вопроса и остановись; подсказку с командой давай всегда,
     номер полный:
     - задача не в архиве — «сначала нужен анализ: `/sae:task analyze <номер>`»;
     - `archived=yes` — «задача в архиве, анализа нет — разбивать нечего; если всё же нужно —
       `/sae:task analyze <номер>`, он сначала спросит про архив»;
   - `archived=yes` — скажи, что задача в архиве, и спроси выбором: **Не трогать (рекомендую)** ·
     **Разбивать всё равно**. Дальше — только по второму; первый или ответ в «Другое», который
     не разрешает разбивку, — остановись.
3. Сверь анализ с подзадачами, путь — из `FOUND`:

   ```
   sh scripts/split.sh '<папка задачи>'
   ```

| Вывод | Что сделать |
| --- | --- |
| `PLAN <папка>` | шаг 4 |
| `QUESTIONS_OPEN <папка>` | в анализе есть неотвеченные вопросы — перечисли их по строкам `question=` и остановись: подзадачи делятся после ответов. Ответы записываются у вопросов (`analyze`, раздел «Ответы на вопросы») |
| `NO_SPLIT <папка>` | в разделе 7 разбивки нет (`reason=` — почему): работа идёт прямо по анализу. Ничего не создавай |
| `NO_TABLE <файл>` | в разделе 7 нет ни таблицы, ни «нет: …»; анализ надо дополнить (`analyze` → «дополнить»). Сам не правь |
| `BAD_TABLE <файл>` | таблица раздела 7 не по шаблону: перескажи строки `line=<номер строки> <что>` (`header` — заголовок не «№ \| Подзадача \| Где \| Зависит от \| Размер»; `separator`, `cells=N`, `number`, `dup`, `title`, `table-and-none` — и таблица, и «нет: …»). Анализ дополняет `analyze`; сам не правь |
| `BAD_ANALYSIS <файл> section=N` | в анализе нет раздела `## N.`; анализ не по шаблону — `analyze` → «заново» или «дополнить» |
| `NOT_DIR <…>/подзадачи` | `подзадачи` — файл, а не папка; скажи и остановись |
| любой другой | перескажи вывод как есть и остановись |

4. Строки после `PLAN` — по одной на строку раздела 7, затем про лишние файлы. Нет ни `new`, ни
   `draft` — доложи состояние (шаг 8) и остановись.

| Строка | Что значит | Что делать |
| --- | --- | --- |
| `П<N> new <подзадача>` | файла ещё нет | создать — шаг 5 |
| `П<N> draft <файл>` | заготовка есть, не дописана (остались метки) | дописать — шаг 6 |
| `П<N> ok <файл>` | готова | не трогать |
| `П<N> changed <файл>` + `was=`, `now=`, `unfilled=` | строка в анализе изменилась после создания файла | не трогать, сообщить: было, стало; `unfilled=yes` — и что файл не дописан |
| `П<N> foreign <файл>` | файл с этим номером без шапки `sae: subtask` (сделан руками) | не трогать, сообщить |
| `П<N> dup <файл>` | у номера несколько файлов (по строке на каждый) | не трогать, сообщить: какой лишний, решает владелец |
| `gone <файл>` | номера файла больше нет в разделе 7 | не трогать, не удалять, сообщить |
| `extra <имя>` | в `подзадачи/` не `NN_<имя>.md` | не трогать, сообщить |
| `dep.missing=П<N> П<M>` | «Зависит от» у `П<N>` ссылается на `П<M>`, которой нет | сообщить: в анализе ошибка |

5. Для каждой строки `new` собери имя файла из названия подзадачи по правилам шага 3
   `steps/new.md` (строчные, пробелы — дефис и т. д.; обратные кавычки
   `` ` `` тоже убери). Номер в имя не ставь. Запусти скрипт **один раз на все `new` сразу**, каждый
   аргумент — `<N>=<имя>` в одинарных кавычках:

   ```
   sh scripts/split.sh --create '<папка задачи>' '1=<имя>' '3=<имя>'
   ```

| Вывод | Что сделать |
| --- | --- |
| `CREATED <папка>/подзадачи` + `file=<путь>` | заготовки созданы; допиши каждую — шаг 6 |
| `BAD_NAME <имя> …` | имя не подошло (`number` — начинается с номера, `extension` — с `.md`); собери другое и запусти заново |
| `MISSING П<N>` | передал не все `new`; запусти со всеми |
| `NOT_NEW П<N> <состояние>` / `NO_ROW <N>` / `DUP_ARG <N>` / `BAD_ARG <…>` | аргументы не сходятся с планом; перезапусти шаг 3 и собери заново |
| `EXISTS <файл>` | файл появился, пока работали; перезапусти шаг 3 |
| любой другой | перескажи вывод как есть (вторая строка — системная ошибка); строки `file=` — заготовки, что успели создаться |

6. Допиши каждую заготовку — `new` из `CREATED` и `draft` из плана:
   - прочитай `анализ.md` целиком и файл подзадачи; можно смотреть код, документацию, KB, но
     **только читать**, как в `analyze`;
   - замени **каждую** метку `<!-- заполнить: … -->` текстом по её подсказке; меток не должно
     остаться ни одной — по ним `split` узнаёт недописанный файл;
   - шапку `---`…`---`, заголовок `# П<N>. …` и паспорт (таблицу «Задача / Где / Зависит от /
     Размер») не меняй — их пишет скрипт, по `source:` он узнаёт изменения в анализе;
   - шаги — `- [ ] 1. <шаг> — S` по порядку с 1, размер S, M или L; галочки не ставь;
   - «Как пойму, что готово» — проверяемые признаки галочками `- [ ] …`, без «работает хорошо»;
   - «Где менять» — таблица `| Файл | Что |`; файлов не знаешь — «нет: потому что …»;
   - «Из анализа» — ссылки на разделы: `[раздел 4](../анализ.md#4-решение)`, ответы — `В1`;
   - бери только то, что есть в анализе и в коде; чего нет — не придумывай, а скажи в докладе,
     что в анализе не хватает;
   - выноски `> [!NOTE]` и подобные не используй — только цитаты с эмодзи: 💡 ℹ️ ⚠️.
7. Когда все файлы дописаны, сверь снова — та же команда, что в шаге 3. Каждый файл, который ты
   дописал, должен стать `ok`. Стал `changed` или остался `draft` — ты задел шапку, заголовок или
   паспорт либо оставил метку: верни их как в прочитанной заготовке, допиши метки и сверь ещё
   раз. Чужие строки (`changed` у файлов, которых ты не трогал, `gone`, `extra` и прочие) — как в
   шаге 4, только сообщить.
8. Доложи:
   - созданные и дописанные файлы — путями, по каждому одна строка «Коротко»;
   - что не тронуто и почему: `ok`, `changed` (было → стало), `foreign`, `dup`, `gone`, `extra`,
     `dep.missing`;
   - чего не хватило в анализе, если такое было.

## Чего не делать

- Не создавать файлы в `подзадачи/` руками — только скриптом `--create`.
- Не трогать файлы `ok`, `changed`, `foreign`, `dup`, `gone` и `extra`: не править, не удалять,
  не переименовывать. Изменения в анализе по ним решает владелец.
- Не править `анализ.md` и `задача.md`, даже если в разбивке ошибка: сообщить.
- Не ставить галочки в шагах и признаках готовности.
- Не создавать карточку, план и другие файлы задачи: у них свои этапы.

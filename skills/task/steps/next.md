# next — что дальше по задаче

Смотрит, на каком этапе задача, и предлагает продолжение меню выбором: рекомендуемый пункт —
первым, свой ответ — в «Другое». Пункты меню запускают готовые действия (`analyze`, `split`) или
ведут работу по подзадаче. Сам `next` пишет только скриптами `mark.sh` и `close.sh`; меняет код
и файлы проекта только в шаге подзадачи, который владелец выбрал.

Номер задачи в ответах и в пунктах меню — полный, с нулями, как в имени папки: `024`.

## Порядок

1. Задача — всё, что в аргументах после `next`: полный путь к папке задачи или её номер.
   Папка с именем из одних цифр — передай её как путь: `./123`. Аргумента нет — возьми
   последние задачи и спроси «Какую задачу вести?» по шагу 1
   `${CLAUDE_SKILL_DIR}/steps/analyze.md`; выбранная — аргумент шага 2.
2. Найди задачу скриптом, аргумент — в одинарных кавычках (кавычку внутри — как `'\''`):

   ```
   sh ${CLAUDE_SKILL_DIR}/scripts/locate.sh '<путь или номер>'
   ```

   Первая строка не `FOUND` — доложи по таблице шага 2 `${CLAUDE_SKILL_DIR}/steps/analyze.md`
   и остановись; `AMBIGUOUS` — выбор по той же таблице и снова этот шаг. После `FOUND`:
   - `task=empty` — скажи, что сначала владелец заполняет `задача.md` («Что хочу», «Как пойму,
     что готово»), дай путь к файлу и остановись;
   - `task=missing` — в папке нет `задача.md`; скажи и остановись, файл сам не создавай;
   - `archived=yes` — задача закрыта и лежит в архиве; скажи это с путём и остановись;
   - `analysis=none` — меню «Анализа нет» (ниже); дальше не иди.
3. Сверь анализ с подзадачами (только чтение), путь — из `FOUND`:

   ```
   sh ${CLAUDE_SKILL_DIR}/scripts/split.sh '<папка задачи>'
   ```

| Вывод | Меню |
| --- | --- |
| `QUESTIONS_OPEN` | «Открытые вопросы» |
| `NO_SPLIT` | «Без разбивки» |
| `PLAN`, все строки раздела 7 — `new` | «Разбивка есть, подзадач нет» |
| `PLAN`, есть файлы подзадач | шаг 4 |
| `NO_TABLE` / `BAD_TABLE` / `BAD_ANALYSIS` | перескажи, что не так (по таблице шага 3 `${CLAUDE_SKILL_DIR}/steps/split.md`), и меню «Анализ не по шаблону» |
| любой другой | перескажи вывод как есть и остановись |

4. Состояние подзадач:

   ```
   sh ${CLAUDE_SKILL_DIR}/scripts/progress.sh '<папка задачи>'
   ```

   Предупреждения из вывода `split.sh` шага 3, если они есть, — `changed` (было → стало), `gone`,
   `foreign`, `dup`, `extra`, `dep.missing` — напиши обычным сообщением **до** вопроса с меню,
   списком, по строке на каждое. Они не блокируют работу. Файл `gone` `progress.sh`
   по-прежнему считает подзадачей: пока он не закрыт, задача не станет `all=done`; закрыть его
   или убрать — решает владелец, скажи ему об этом. Есть `new` или `draft` — первым пунктом
   меню «Досоздать подзадачи» (`split`), а пункты ниже — следом.

| Вывод `progress.sh` | Что значит |
| --- | --- |
| `PROGRESS <папка>` | дальше строки по подзадачам и последняя строка «что дальше» |
| `П<N> <состояние> steps=K/M checks=a/b deps=… blocked=yes\|no [line=…] file=<имя>` | `open` — в работе; `done` — закрыта; `draft` — не дописана (`split` допишет); `nosteps` — в разделе «2. Шаги» нет шагов; `badsteps` — шаги не по виду `- [ ] N. …` с 1 подряд (`line=` — первая неверная строка); `dup` — у номера несколько файлов. `blocked=yes` — не все «Зависит от» закрыты |
| `next=П<N> step=K` | рекомендуемая — П<N>, её шаг K |
| `next=П<N> close` | у рекомендуемой П<N> все шаги отмечены — пора закрывать |
| `next=none` | открытые есть, но взять нечего: все заблокированы или не готовы |
| `all=done` | все подзадачи закрыты |
| `NO_SUBTASKS <папка>` | файлов подзадач нет (все строки — `new`): меню «Разбивка есть, подзадач нет» |
| любой другой | перескажи вывод как есть и остановись |

## Меню

Спрашивай выбором; в вопросе — номер и название задачи. Рекомендуемый вариант — первым, с
пометкой «(рекомендую)». После выполненного пункта, если не сказано иначе, вернись к шагу 3 и
покажи меню заново.

| Этап | Пункты |
| --- | --- |
| Анализа нет | **Сделать анализ** — по `${CLAUDE_SKILL_DIR}/steps/analyze.md` с шага 4 · **Показать `задача.md`** |
| Открытые вопросы | **Ответить на вопросы по одному** — ниже · **Дополнить анализ** · **Написать анализ заново** |
| Разбивка есть, подзадач нет | **Разбить на подзадачи** — по `${CLAUDE_SKILL_DIR}/steps/split.md` с шага 3 · **Дополнить анализ** · **Задать ещё вопросы** — владелец называет, что не ясно; ты записываешь это вопросами в раздел 6 как «дополнить» |
| Без разбивки | **Делать по анализу** — ниже · **Дополнить анализ** · **Закрыть задачу** — ниже |
| Анализ не по шаблону | **Дополнить анализ** · **Написать анализ заново** |
| `next=П<N> step=K` | **Взять П<N> в работу: шаг K из M** — с текстом шага · **Другая подзадача** · **Сводка по подзадачам** |
| `next=П<N> close` | **Закрыть П<N>** — ниже · **Другая подзадача** · **Сводка по подзадачам** |
| `next=none` | скажи, почему брать нечего (кто кого блокирует, какие не готовы) · **Другая подзадача** · **Сводка по подзадачам** |
| `all=done` | **Закрыть задачу** · **Добавить подзадачу** — «дополнить» анализ новой строкой раздела 7, затем `split` · **Оставить открытой** — остановись |

- **Дополнить анализ** и **Написать анализ заново** — по `${CLAUDE_SKILL_DIR}/steps/analyze.md`,
  ветка `analysis=exists`, уже без вопроса «дополнить или заново».
- **Сводка по подзадачам** — выведи таблицу обычным сообщением, затем задай то же меню без
  сводки. Строки — из вывода `progress.sh`, название — из заголовка файла подзадачи:

  ```
  | № | Подзадача | Состояние | Шаги | Признаки | Зависит от |
  | --- | --- | --- | --- | --- | --- |
  | П2 | Кнопка и прогресс | open, ждёт П1 | 0/4 | 0/4 | П1 |
  ```
- **Другая подзадача** — спроси выбором из незакрытых (до четырёх, остальные номером в «Другое»).
  Пункт — номер и название; в описании — что будет сделано: у `open` — «шаг K из M: <текст
  шага>» (K — первый неотмеченный; длинный текст сократи), все шаги отмечены — «закрыть»;
  `blocked=yes` — и кого ждёт. Выбор подзадачи и есть выбор этого шага — второй раз не
  спрашивай:
  - `open`, `blocked=yes` — сначала сообщением предупреди, какие «Зависит от» не закрыты; не
    запрещай;
  - `open` с неотмеченным шагом — сразу «Работа по подзадаче» с шагом K; все шаги отмечены —
    сразу «Закрыть подзадачу»;
  - `draft` — её допишет `split`; `nosteps`, `badsteps`, `dup` — скажи, что не так в файле и
    что поправить его должен владелец; не правь сам.

## Ответы на вопросы

Бери открытые вопросы раздела 6 по порядку номеров, **по одному**. По каждому: прочитай вопрос и
то, на что он опирается в анализе; объясни простыми словами, о чём он и что от ответа зависит;
спроси выбором, рекомендуемый вариант — первым, свой ответ — в «Другое». Ответ запиши по
разделу «Ответы на вопросы» `${CLAUDE_SKILL_DIR}/steps/analyze.md` и обнови зависимые разделы.
Владелец ответил вопросом — ответь на него и спроси снова. После последнего — шаг 3.

## Работа по подзадаче

1. Прочитай файл подзадачи целиком и разделы `анализ.md`, на которые он ссылается.
2. Сделай **только шаг K** — тот, что выбрал владелец. Следующие шаги не начинай.
3. Доложи, что сделано и где, и спроси выбором:
   - **Принять и отметить** — отметь шаг скриптом и вернись к шагу 3 порядка: дальше снова
     меню, первым — следующий шаг:

     ```
     sh ${CLAUDE_SKILL_DIR}/scripts/mark.sh step '<папка задачи>/подзадачи/<файл>' K
     ```

   - **Доработать** — что не так, владелец пишет в «Другое»; доработай и спроси снова;
   - **Отложить шаг** — остановись; ничего не отмечай и не записывай.

| Вывод `mark.sh` | Что сделать |
| --- | --- |
| `MARKED <файл>` + `step=K`, `steps=D/M` | шаг отмечен; шаг 3 порядка |
| `NOT_NEXT K` + `first=F` | отмечать можно только первый неотмеченный шаг F; скажи и вернись к шагу 3 |
| `ALREADY K` / `ALREADY_DONE <файл>` | шаг уже отмечен / подзадача уже закрыта; шаг 3 |
| `DRAFT`, `BAD_STEPS` (+ `line=`), `NO_STEPS`, `NO_STEP K`, `NOT_SUBTASK` | файл не годится для отметки; скажи, что именно, и остановись |
| любой другой | перескажи вывод как есть (вторая строка — системная ошибка) и остановись |

## Закрыть подзадачу

1. Проверь **фактом** каждый признак раздела «3. Как пойму, что готово»: запусти, прочитай код,
   сверь файлы. Покажи список: номер признака по порядку, ✅ или ⛔, чем проверено.
2. Спроси выбором: **Закрыть** · **Доработать**; есть ⛔ — первым **Доработать**.
3. **Закрыть** — отметь только признаки ✅, их номера через пробел; ⛔ остаются неотмеченными:

   ```
   sh ${CLAUDE_SKILL_DIR}/scripts/mark.sh done '<папка задачи>/подзадачи/<файл>' 1 3
   ```

   `CLOSED <файл>` + `checks=a/b` — подзадача закрыта; шаг 3 порядка. `STEPS_OPEN` + `first=` —
   не все шаги отмечены, вернись к ним. `NO_CHECK N` — признака N нет, пересчитай номера. Любой
   другой — перескажи и остановись.
4. **Доработать** — что не так, владелец пишет в «Другое» (при ⛔ — сначала их); доработай и
   проверь признаки снова.

## Делать по анализу

Задача без подзадач: веди работу по решению из раздела 4 анализа частями, после каждой —
доложи и спроси **Принять** · **Доработать**. Галочек и файлов следа нет. Когда решение сделано —
проверь фактом признаки «Как пойму, что готово» из `задача.md` (✅/⛔) и предложи **Закрыть
задачу**.

## Закрыть задачу

Есть строки `new` в выводе `split.sh` — предупреди: эти подзадачи так и не созданы. Затем:

```
sh ${CLAUDE_SKILL_DIR}/scripts/close.sh '<папка задачи>'
```

| Вывод | Что сделать |
| --- | --- |
| `ARCHIVED <папка>` + `to=<куда>` | задача закрыта; скажи, куда ушла папка. Номер тот же — `next`, `analyze` находят её по нему |
| `SUBTASKS_OPEN <папка>` + `open=<файл>` | не все подзадачи закрыты: перечисли и спроси выбором **Оставить открытой** · **Закрыть всё равно**. Только по второму — тот же вызов с `--open-ok` перед папкой |
| `EXISTS <куда>` | в архиве уже есть папка с таким именем; скажи, решает владелец |
| `NOT_IN_TASKS <папка>` | задача лежит не в папке задач — архив не определить; скажи и остановись |
| `ALREADY_ARCHIVED <папка>` | уже в архиве |
| любой другой | перескажи вывод как есть (вторая строка — системная ошибка) и остановись |

## Чего не делать

- Не ставить галочки руками и без «принять» владельца; не отмечать шаги через один.
- Не закрывать подзадачу без проверки признаков и не отмечать признаки ⛔.
- Не переносить и не удалять папки задач руками — только `close.sh`.
- Не править `задача.md`; анализ — только через пункты «дополнить», «заново» и ответы на вопросы.
- Не начинать следующий шаг или следующую подзадачу без выбора владельца.
